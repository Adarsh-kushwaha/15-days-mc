How to actually get these "by heart"

Memory ≠ re-reading solutions. It comes from retrieval under pressure + spacing. Here's the method baked into the timeline.

The daily loop (per problem)

  1. Understand cold — restate the problem + constraints in your own words.
  2. Recall the pattern — before coding, say which technique applies and why.
  3. Code without looking — full solution from scratch; run it mentally.
  4. State complexity — time & space, and the bottleneck.
  5. Self-grade — peek at a solution only after a real attempt; note what you missed.

The spacing rule (what makes it stick)

  • Phase 1: first exposure + same-week revisit.
  • Phase 2: re-solve each topic from memory (gap of weeks).
  • Phase 3: random recall — you don't know what's next, like a real interview.
  • Phase 4: verbalize all 50 approaches in one sitting. Explain pattern + complexity in 60s each → it's in long-term memory.

The < 40-minute discipline

Use a visible timer. Max 5 min thinking before coding. Stuck at 25 min? Peek at one hint and continue. If a problem takes > 40 min, it joins your re-drill list for the next speed day. Speed comes from recognizing the pattern fast, not typing faster.

Interview-day reflexes

  • Clarify ranges, duplicates, empty cases before coding.
  • Talk while you code — silence reads as being stuck.
  • Trace one example by hand to catch off-by-one bugs.
  • Know the brute force first, then optimize.

Core patterns powering all 50
