How to actually get these "by heart"

Memory ≠ re-reading solutions. It comes from retrieval under pressure + spacing. Here's the method baked into the plan.

The daily loop (per problem)

  1. Understand cold — restate the problem + constraints in your own words.
  2. Recall the pattern — before coding, say out loud which pattern/data structure applies and why.
  3. Code without looking — write the full solution from scratch. Compile/run mentally.
  4. State complexity — time & space, and the bottleneck.
  5. Self-grade — only peek at a solution after a real attempt. Note exactly what you missed.

The spacing rule (this is what makes it stick)

  • Phase 1: first exposure + same-week revisit.
  • Phase 2: re-solve each topic from memory (gap of ~1–3 weeks).
  • Phase 3: random recall — you don't know which problem comes next, just like a real interview.
  • Phase 4: verbalize all 50 approaches in one sitting. If you can explain pattern + complexity in 60 sec each, it's in long-term memory.

The < 40-minute discipline

Always use a visible timer. Spend max 5 min thinking before you start coding. If you're stuck at the 25-min mark, peek at one hint, then keep going. After solving, if it took > 40 min, that problem goes on your "re-drill" list for the next speed day. Speed comes from recognizing the pattern fast, not typing faster.

Interview-day reflexes to drill

  • Clarify input ranges, duplicates, empty cases before coding.
  • Talk while you code — narrate the plan; silence reads as being stuck.
  • Trace one example by hand after coding to catch off-by-one bugs.
  • Know the brute force first, then optimize — interviewers love the journey.

  • Hashing / frequency maps
  • Fast & slow pointers · in-place reversal
  • Monotonic stack · deque
